### P1 — Phải sửa trong v2.0.4

#### F01 — Next App Router payload bị 404 khi điều hướng

- Bằng chứng runtime: từ Dashboard sang Analytics tạo `18` request, trong đó nhiều request như `/analytics/__next.analytics.__PAGE__.txt` và các payload của Orders, Imports, Targets, Accounts, Settings trả `404`.
- Bằng chứng filesystem: static export phát hành file dạng `/analytics/__next.analytics/__PAGE__.txt`; `StaticFiles(html=True)` không ánh xạ dạng URL phẳng sang file lồng thư mục.
- Next.js xác định static export có payload cho client navigation và có thể phục vụ bằng web server tĩnh; vì vậy boundary cần sửa là resolver/hosting của ứng dụng, không phải bỏ App Router: [Next.js Static Exports](https://nextjs.org/docs/app/guides/static-exports).
- Điểm liên quan:
  - `web/src/components/app-shell.tsx:49-55`
  - `affiliate_report/api.py:1351-1353`
- Tác động: tạo network noise trên mọi lần prefetch/đổi route, làm navigation phụ thuộc fallback và tăng nguy cơ màn hình stale sau nâng cấp.
- Hướng xử lý: thêm static-export resolver fail-closed ở backend để ánh xạ đúng các RSC payload đã tồn tại trong `web/out`; không dùng rewrite tùy ý và không cho phép path traversal.
- Nghiệm thu: điều hướng qua toàn bộ route bằng `next/link` không còn request RSC `404`; route không tồn tại vẫn trả `404` đúng.

#### F02 — Cache/service worker chưa gắn với phiên bản ứng dụng

- `web/public/sw.js:1` dùng cache cố định `tiktok-affiliate-report-shell-v5`.
- `web/public/sw.js:4-17` thiếu `/settings/preferences/` trong shell ban đầu.
- `web/public/sw.js:55-59` trả Dashboard cache cho mọi navigation thất bại, có thể hiển thị sai trang tại URL hiện tại.
- Launcher log từng ghi stale hashed CSS `/_next/static/chunks/...css 404` sau update; đây là dấu hiệu cache và bộ static asset không đồng bộ ở boundary nâng cấp.
- Hướng xử lý:
  - phát sinh cache namespace từ `APP_VERSION` trong build;
  - cache đủ route public được đóng gói;
  - xóa cache cũ khi activate;
  - dùng trạng thái offline/restarting rõ ràng thay vì âm thầm trả Dashboard cho route khác;
  - không cache response 404 hoặc private API/auth.
- Nghiệm thu: nâng `v2.0.3 → v2.0.4` qua UI không phát sinh hashed JS/CSS 404, không hiển thị sai route và service worker mới chiếm quyền sau restart.

#### F03 — Focus ring không đạt contrast

- `web/src/app/globals.css:43` dùng `rgba(122, 61, 40, 0.24)`; runtime keyboard xác nhận outline 3 px đúng token này.
- Contrast sau alpha compositing chỉ khoảng `1,50:1` trên trắng và `1,48:1` trên nền app; dark theme khoảng `1,88:1`.
- Tác động: người dùng bàn phím khó xác định phần tử đang focus; không đạt mục tiêu WCAG 2.2 AA cho focus appearance.
- Hướng xử lý: dùng focus token cyan/neutral dạng solid hoặc dual-ring, đạt tối thiểu `3:1` với nền liền kề ở light/dark và không bị cắt trong dialog/sheet.
- Nghiệm thu: keyboard walkthrough cho sidebar, command palette, filter sheet, form và dialog; test contrast token tự động.

#### F04 — Muted text light-theme chưa đạt 4,5:1

- `web/src/app/globals.css:33`: `--text-muted: #72807d`.
- Contrast: `4,12:1` trên trắng và `3,73:1` trên `--bg`.
- `web/src/app/globals.css:1792` dùng token này cho nhãn capability trên Settings OIDC/Postgres; flow local hiện không render nên axe local không bắt được.
- Hướng xử lý: nâng token hoặc dùng `--ink-soft` cho text cỡ nhỏ; giữ semantic hierarchy bằng weight/spacing thay vì giảm contrast.
- Nghiệm thu: capability gates ở light/dark đều đạt WCAG 1.4.3; thêm a11y test cho fixture shared/OIDC.
